# Рефлексія. Заняття 36. SQLAlchemy ORM

## Що я навчилася?

- Навіщо потрібен ORM — абстракція над SQL, робота з Python об'єктами
- Як використовувати SQLAlchemy для моделювання даних
- Декларативне визначення моделей через класи Python
- CRUD операції без написання сирого SQL
- Relationships між моделями (JOIN автоматично)
- Eager loading для оптимізації запитів

## Найскладніший момент

Зрозуміння різниці між lazy loading і eager loading, і коли який використовувати.

## Еврика-момент!

Relationship в SQLAlchemy автоматично робить JOIN — не треба писати SQL запити вручну!

## Порівняння SQL vs ORM

ORM зручніший для розробки:
- Менше коду
- Безпека від SQL injection автоматично
- Python замість SQL
- Але іноді менший контроль над оптимізацією

SQL потрібен для:
- Складних оптимізацій
- Коли потрібен повний контроль
- Системах, де ORM не можна використовувати

## План на Django

Django ORM схожий на SQLAlchemy, але більш інтегрований з фреймворком. Можливо, буде простіше через вбудовані адмін-панелі та міграції.
